# 对标逆向：架构与登录实现（hongguo-player v1.2.28）

> 对象：`D:\AAAtest\11111\短剧播放器.exe`（28.5 MiB，单文件）
> 方法：二进制字符串 / Go 符号表 / 嵌入前端资源静态提取（**只读分析，未运行、未抓包**）
> 用途：为 [重做方案-v2.md](./重做方案-v2.md) 与 [登录方案-v2-扫码自注册.md](./登录方案-v2-扫码自注册.md) 提供事实基础
> 结论：**它不是 WebView2 壳套网页，而是一个自带后端（Go）的本地应用；登录是「自注册设备 + passport 网页扫码」，无换绑风险。**

---

## 一、技术形态（已证实）

| 项 | 证据 | 结论 |
|---|---|---|
| 运行时 | 符号 `hg-go/cmd/hgplayer/main.go`、`HG_WV2_USER_ARGS`、`EmbeddedBrowserWebView.dll` | **Go 主程序 + WebView2 渲染** |
| 桥接 | 字符串 `Wails 内部结构不符 (Invoke)`、`Error calling 'runtime.Quit'` | **Wails v2**（前端直接调 Go 方法，无本地 HTTP 端口） |
| 前端 | 嵌入 HTML：`<title>短剧播放器</title>`、`/assets/index.38dab12e.js`、`/assets/index.edb05cd8.css` | **Vite 构建的 SPA**（Vue 3 反应式代码特征明显，属推测） |
| 体积 | 28.5 MiB 单 exe + ffmpeg 5.02 MiB（外置）+ WebView2/HEVC 安装器 | 与文档「17.7 MB zip」口径一致（zip 含全部 4 个文件） |
| Go 依赖 | `github.com/tetratelabs/wazero`、`andybalholm/brotli`、`ed25519`、`chacha20poly1305` | 含 WASM 运行时、brotli 资源压缩、签名/加密 |

**关键差异**：它把「服务端」做进了客户端（Go），所以没有本地端口、没有 Node；我们的项目是 Electron + 独立 HTTP 服务端。

## 三、登录实现（重点）

### 3.1 三个 Wails 方法，说明三种登录入口

从符号表直接读到：

| 符号 | 含义 |
|---|---|
| `App.QRLoginStart` / `App.QRLoginPoll` / `App.QRLoginCancel` | **扫码登录**（轮询式，前端只管画二维码） |
| `App.Login` | 另一条登录编排（短信/验证码路径，符号 `flow: 登录失败且非 MFA: %s`） |
| `App.LoginRegions` / `flow/regions.go` | 登录时选择区域/机房 |
| `App.RetryDeviceRegister` / `deviceBootstrap.*` | 设备身份没就绪时可以重试注册 |

配套字符串：

- `/passport/web/get_qrcode/`（取二维码）
- `/passport/web/check_qrconnect/`（轮询确认）
- `扫码登录未完成, 请重试`、`取二维码失败, 请稍后重试`、`登录失败`、`auth:expired`
- `passport_jssdk_version`、`passport-sdk-settings`、`new_authn_sdk_version`、`passport_support_flow`
- `x-tt-passport-csrf-token`、`passport_csrf_token_default`（`Session.passportCSRF` 负责拿）
- `passport_mfa_retry_tag`、`flow: 登录失败且非 MFA`（MFA 二次验证分支）

**结论**：主路径是**网页 passport 的扫码接口**（不弹浏览器、不换绑、不依赖手机号），拿到的是 `sessionid / sid_guard / uid_tt / d_ticket` 这套 Cookie。短信路径存在，但需要过人机验证（`发送验证码需要人机验证`），不是首选。

### 3.2 设备身份：自己注册，不等外部

- 接口：`/service/2/device_register/`（字符串确证）
- 流程符号：`deviceBootstrap.ensure → prepare → run → readyDevice → persist → registerSpare → retry`
- 加密：`register: TTEncrypt 加密失败`、`register: 响应解密失败`、`register: 请求失败`、`register: 未设置设备指纹` → **请求 TTEncrypt 加密、响应加密回传，且必须先有设备指纹**
- 兜底：`pkg/hgapi/iidpool.go`（install_id 池）、`spare.go`（备用设备）、`RetryDeviceRegister`
- 落盘：`device.json`（字段见下）

**这与我们的 `session-device.json` 结构完全一致**（从 Go 类型字符串读出）：

```go
DeviceBrand, DeviceType, OSVersion, OSApi, Resolution, DPI,
UserAgent, Channel, OdinTT, DeviceToken, TtReq, StoreRegion
```

→ 意味着：**我们现有的设备档案格式可以直接复用，不用改数据结构**；要补的是「注册」这一步（它产生这些字段，而不是从别处导入）。

### 3.3 请求签名（它不依赖外部 exe）

- 头：`X-Argus`、`X-Gorgon`、`X-Helios`、`X-Medusa`、`X-Ladon`，另有 `x-ss-dp`、`x-ss-req-ticket`、`x-tt-dt`
- 实现：`pkg/crypto/{gorgon,helios,medusa,medusa_v5,sm3,ttencrypt,xor}.go`，`pkg/register/signer_pure.go`
- 另有 `Session.PreviewSignature` → 进度条预览图走**独立签名 URL**

**结论**：对标项目已把签名纯 Go 化。我们的 `hgsigner.exe` 是同一算法族的外挂进程，方向没错，但「外挂 + 不可复现源码」在重做里应改成**可构建的库**（见 v2 决策 D2）。

### 3.4 会话持久化

- `hgplayer.db`（`local_favorite` / `local_like` / `progress` / `download` 表，含 `synced` 标记）
- `device.json`、`window.json`、`datadir.json`、`config.json`、`result.json`、`events.json`、`status.json`
- `Session.SetCookieString / SetUID / SetToken / CookieString` + `mergeCookies`

→ 设计要点：**Cookie、设备、UID、Token 分开存**，Cookie 合并而不是覆盖（我们现有的 `saveSession` 是整串覆盖，容易丢 `store-region` 等持久项）。

## 五、它做对而我们没做的事（按价值排序）

| # | 做法 | 我们的现状 | 价值 |
|---|---|---|---|
| 1 | 设备身份**自注册**（TTEncrypt + 指纹） | 靠导入别人的设备身份 | 摆脱第三方依赖，登录才能独立 |
| 2 | 登录走 **passport 扫码接口**（无窗口） | 内嵌浏览器窗口点登录 / 短信换绑 | 稳定、无换绑风险、跨版本抗改版 |
| 3 | 签名**纯代码**、随主程序 | 外挂 `hgsigner.exe`，源码不在库 | 可复现、可调试、省 7.7 MB |
| 4 | 媒体**存 CENC 原件**、本地解密代理 | 转码成 MP4（8–15 秒/集） | 下载秒开、省磁盘、省 CPU |
| 5 | `multi_video_model` 多清晰度 | 单档、跟随源分辨率 | 1080/720/480 三档才有得选 |
| 6 | Cookie/UID/Token 分离 + merge | 整串覆盖 | 会话更稳，少"突然掉登录" |
| 7 | 更新清单 ed25519 签名 + 蓝奏云兜底 | 无自动更新 | 可安全更新 |
| 8 | 进度条预览图独立签名 URL | 无 | 体验细节 |
| 9 | 原生解码三档（GPU/ffmpeg/WebView） | 仅 ffmpeg 软解 + 转码 | 低配机不卡 |
| 10 | 数据自检/修复（`store/repair.go`、`integrity.go`） | 无 | 抗损坏 |

## 六、不能照搬的（要避的坑）

1. **依赖 WebView2 + HEVC 扩展**：这是它 17.7 MB 的代价，也是它在精简系统上翻车的原因。我们若不换栈，没必要为了体积重蹈。
2. **Go + Wails 的桥接**：前端直接调 Go 方法，等于前后端没有契约层，功能一多就难演进。我们保留 HTTP 契约更利于 M1~M4 并行。
3. **闭源 + 未签名 + 自替换更新**：杀软误报的根源。我们做更新必须签名清单 + 用户确认。
4. **`stealth.go` / `bosskey.go` / `loopproxy`**：属于规避检测类实现，不移植；本地解密代理可以用正当代替（回环 HTTP + 随机 token）。
