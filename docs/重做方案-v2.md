## 二、五个决策（D1–D5）

| # | 决策 | 选项 | 建议 | 理由 |
|---|---|---|---|---|
| **D1** | 技术栈 | A. Electron + TS（前端 Vite/React，服务端 Node）<br>B. Go + Wails（与对标同构）<br>C. Electron 壳 + Go 助手进程（混合） | **C** | 前端与桌面壳沿用我们已验证的 Electron 经验（启动器/安装器/小窗/多显示器）；**签名与设备注册用 Go**，因为 `TTEncrypt`/`ss_app_log` 容器/x-Gorgon 一族移植到 TS 风险最高，而 Go 侧已有同族实现可复用 |
| **D2** | 签名 | A. 继续外挂 `hgsigner.exe`（不可复现）<br>B. 自建 Go 库，源码入库 + 构建脚本 | **B** | 现在 exe 的源码在 `.gitignore` 的 `.research/` 里，换机器就断；B 让签名可构建、可单测 |
| **D3** | 媒体 | A. 转码成 MP4（现状，8–15 s/集）<br>B. 存 CENC 原件 + 本地解密代理（对标做法） | **先 A 后 B** | A 已通，保证 M2 能播；B 在 M4 替换（下载秒开、省 CPU），并且它能顺带解决「清晰度」多档问题 |
| **D4** | 数据目录 | A. `%APPDATA%\HorunDrama`<br>B. `%APPDATA%\yimu-theater` | **A** | 主进程已优先它、安装版数据在此；服务端默认值要跟着改（现在两者分叉，是 0.27 的遗留 bug） |
| **D5** | 前端落地 | A. 新建 `apps/web-next` 并行<br>B. 原地重建 `apps/web` | **A** | 旧版要能回退、两套全局样式不能打架；M3 切主后再删旧目录 |

## 三、新架构

```
apps/
├ desktop/                  Electron 主进程（重写，精简）
│   ├ main.cjs              窗口 / 启动器 / 单实例 / 小窗 / 数据目录 / 更新
│   ├ preload.cjs           只暴露：登录三通道、全屏、小窗、选目录
│   └ resources/            icon.*、launcher、ffmpeg、hgsigner（过渡期）
├ core/                     ★ 新增：业务核心（Node，TS，无 UI）
│   ├ http/                 路由/静态/错误码（沿用"绝不伪造 206"的原则，代码新写）
│   ├ device/               设备自举（注册/指纹/池）
│   ├ sign/                 签名（过渡期调 hgsigner，终态换 Go 库）
│   ├ login/                扫码登录协议层（start/poll/cancel）
│   ├ catalog/              目录/搜索/榜单/筛选/演员/合集
│   ├ media/                CENC 解密、本地解密代理、转码、缓存、下载
│   ├ account/              收藏/历史/预约/追更/点赞（全部账号接口）
│   ├ store/                SQLite（进度/追剧/下载/偏好）+ 设置
│   └ updater/              更新清单校验与安装（M6）
├ web-next/                 ★ 新增：新前端（Vite + React + zustand）
│   ├ design/               tokens.css / glass.css / motion.css / icons
│   ├ core/                 playback 状态机 / keyboard / store
│   ├ surface/              PlayerSurface / PlayerChrome
│   ├ modes/                Normal / Feed / Mini
│   └ views/                Theater / Feed / Rank / Category / Library / Search / Settings
└ (旧 web/ server/ 冻结只读)
```

**契约**：前端只通过 HTTP 调 `core`（不用 IPC 传业务数据），主进程只管窗口与系统能力。这样 `core` 可单测、可脱离 Electron 起服务调试。

## 四、里程碑（按"可演示"切，不按模块切）

> 每阶段结束：`pnpm typecheck` 绿 + e2e 对应项绿 + 打一版包（旧版可回退）。

### M0 骨架与设计系统（2–3 天）
- 新建 `apps/web-next`、`apps/core`，互不引用旧代码
- `tokens.css / glass.css / motion.css`；底部胶囊导航 + 顶栏；深浅色
- `apps/core` 起最小 HTTP（`/api/health`、`/api/meta`），前端能连上
- 统一数据目录为 A（D4），启动日志打印
- **验收**：空壳能跑；深浅色都过；`/api/health` 返回版本

### M1 设备与登录（★ 与 M0 并行，3–5 天）
- L0 三个探针（见登录方案 v2 第五章）
- `device/` 自注册；`login/qr` 协议；二维码页面（新前端第一个真实页面）
- 会话三件套落盘；`/api/account/profile` 校验
- **验收**：手机扫码能登录、重启仍登录、日志零凭据

### M2 浏览面（3–4 天）
- 剧场 / 榜单 / 分类 / 搜索（走 `core/catalog`，复用 v1 已验证的接口知识）
- **验收**：四个页面能翻页到 3 页以上；限流有文案

### M3 播放内核（4–5 天，最高风险）
- `playback.ts` 状态机；`PlayerSurface` + `PlayerChrome`；Normal/Mini 两 Mode
- 全屏改窗口级；小窗按真实宽高比
- **验收**：6 项播放断言绿（解码/代理地址/比例/跳转/弹幕/进度落库）；三 Mode 互切不污染

### M4 完整日常（3 天）
- 详情抽屉、追剧（含预约位）、观看记录、设置、快捷键
- 切主：`web-next` → `apps/web`，删旧前端（保留 tag）
- **验收**：25 项 e2e 在新外壳下全绿；设置改目录后重启生效

### M5 功能面对齐（5–7 天）
- Feed 流、弹幕评论、下载管理页、清晰度三档、进度条预览图、上新日历、追更提醒
- 账号写操作：预约/点赞/追更（**全部二次确认**）
- **验收**：与对标功能清单逐项对勾（见对标逆向第四章接口表）

### M6 发布（2–3 天）
- 自动更新（ed25519 签名清单 + 官方地址）
- 安装器重做、体积记录、回归全跑
- **验收**：能从 v0.27 升级到新版；更新失败可回滚

## 五、必须继承的「教训」（代码重写，经验不重写）

| 坑 | 做法 |
|---|---|
| 启动器 exe 无图标 / 必须 `--no-sandbox` | 重写启动器时 `csc /win32icon:`，并把参数写进构建脚本 |
| 数据目录漂移 | M0 就统一，且**单一来源**（环境变量 > 固定目录） |
| `ELECTRON_RUN_AS_NODE=1` 常驻 | 启动脚本先 `delete` 该变量 |
| 全屏元素被卸载 | 窗口级全屏 + 根节点 class，不做 DOM 全屏 |
| 弹幕用播放时间清理 | 墙钟时间 |
| 滚轮连跳集 | 节流 + `preparing` 忽略 |
| 流媒体伪造 206 | **绝不**；Range 按真实字节 |
| 打包隐藏文件漏打 | 安装器 `customInstall` 处 `attrib +h` |
| PowerShell 改文件乱码 | 用 Node 脚本或编辑器（本机 PowerShell 是 5.1，默认 ANSI） |
| 官网登录是推广页 | 不做网页登录（v2 已改为扫码接口） |

## 七、与 v1 的差异（一句话对照）

| v1 | v2 |
|---|---|
| 换骨架、换皮，不换引擎 | **全部重写**，只留 UI 理念/图标/名称 |
| 登录「保留现状」，排 M5 | 登录按对标**扫码 + 设备自注册**，排 M1 并与 M0 并行 |
| 服务端复用 `apps/server` | 新建 `apps/core` 重写（算法知识参考，不复制） |
| 外挂 `hgsigner.exe` | 过渡期用、终态改为**源码入库的 Go 签名库**（D2） |

| 下载 = 转码 MP4 | 先转码、后改 CENC 原件 + 本地解密（D3） |
| e2e 25 项直接回归 | 先抽选择器层，再让新外壳通过（M0 内完成） |
